# Governance and support

OpenPRISM currently uses a maintainer-led model. The founding maintainer is
responsible for releases, security decisions, scope, and appointing additional
maintainers. Technical decisions should be documented in public issues and
prefer reproducible evidence over authority.

## Roles

- **Contributors** propose issues, documentation, experiments, and code.
- **Maintainers** review changes, enforce project policies, triage reports, and
  cut signed or checksummed releases.

Maintainers may be added after sustained, constructive contributions and an
explicit public invitation. A maintainer may step down at any time. If the
founding maintainer is inactive for 90 days, remaining maintainers may nominate
a successor by documented consensus.

## Support

Use GitHub Discussions for usage and research-design questions and GitHub Issues
for reproducible defects. This project provides no operational SLA and is not a
certified flight, navigation, surveillance, or life-safety system.

Security-sensitive reports follow `SECURITY.md`; all other support is public so
that solutions remain discoverable.
